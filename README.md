```mermaid
flowchart TB
    A[Business needs and raw information] --> B[Requirements and data contracts]
    B --> C[Structured data layer<br/>JSON · spreadsheets · validation]
    C --> D[Application and interface layer<br/>search · forms · dashboards]
    D --> E1[RR3 mobility workflows]
    D --> E2[Zendora commerce workflows]

    F -. improves .-> B
    F -. supports .-> D

    classDef input fill:#0b1020,stroke:#55f2ff,color:#e6f7ff,stroke-width:1.5px;
    classDef data fill:#101a34,stroke:#8b5cf6,color:#f4edff,stroke-width:1.5px;
    classDef product fill:#092a2b,stroke:#14b8a6,color:#e6fffb,stroke-width:1.5px;
    class A,B input;
    class C,D,F data;
    class E1,E2 product;
```

### Engineering principles

- **Schema before scale:** define the shape of data before building many screens around it.
- **Simple by default:** avoid unnecessary complexity when a simpler solution is reliable.
- **Validate at boundaries:** treat external inputs and imported data as untrusted until checked.
- **Security is part of the design:** use least privilege, clear access rules, and sensible request limits.
- **Document the decisions:** write down requirements, assumptions, and trade-offs so systems remain maintainable.
